# to2610-noc 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

2×2 网格上的四核芯片，面向 ECOS 2610 班车。四颗 Hazard3（RV32IMAC，机器态）各占网格的一个结点，核与核之间只经网格发报文；片外的 SPI Flash、SDRAM、串口与 `to2610-kvc` 是同一套，四个核经一个仲裁共用，所以这一颗与 kvc、amp、smp 用同一块底板。

核与网格都不是这个仓写的：核是上游的 Hazard3（黑盒仓 `hazard3`，子模块不动），网格是组织里的 `noc` 库（Bluespec Haskell：五口路由器、每口两级缓冲、XY 路由、每个输出口轮转仲裁、valid/ready 握手），片外存储与外设的控制器取 `to2610-kvc` 那棵源码树。本仓自己写的有五样：`box/NocBox.bsv` 是四份信箱加一页控制寄存器，背后例化网格；`hwsrc/noc_tile.v` 把 Hazard3 的 AHB5 口转成片上总线；`hwsrc/noc_arb.v` 是四路仲裁，连同地址换算与独占访问的预留表；`hwsrc/noc_time.v` 是微秒计数；`patch/noc.patch` 在 kvc 的 `soc.v` 上拿掉 KianV 核、接进上面几样。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 核 | 四颗 Hazard3 | RV32IMAC、Zbb、Zicsr、Zifencei、Zicntr，只有机器态；`mhartid` 是结点号 0 到 3。开 Zbb 是因为上游的 ALU 只在开了它时把 `amomaxu`、`amominu` 当无符号比 |
| 网格 | 2×2，XY 路由 | 单片报文：目的 8 位、源 8 位、载荷 32 位；源结点号由硬件填 |
| 信箱 | 每核一份 | 发送不等人，网格不收就丢并记一笔；接收缓冲 4 个包，可报外部中断 |
| 存储 | 片外 SDRAM 32 MiB、SPI Flash | 每核私有 6 MiB，四核共享 8 MiB；Flash 四个核都读得到 |
| 原子操作 | LR、SC 与 AMO 跨核原子 | 仲裁里按物理地址记预留，别的核写了被预留的字，预留作废 |
| 计时器与核间中断 | CLINT 照标准的排法；控制页的 `IPI` | `mtime` 四个核共用，`mtimecmp` 与 `msip` 每核一格，四个核都看得见；FreeRTOS 的 RISC-V 移植按 `mhartid` 找自己那一格，不用改 |
| 核的起停 | 控制页的 `RUN` | 复位后只有 0 号核跑；收回一个核要等它手上那次访问做完 |
| 外设 | 同 `to2610-kvc` | 串口 0、SD 卡口、SPI 网卡口、1 位 GPIO，四个核都看得见；串口的中断只进 0 号核 |

### 四个核怎么起

复位后只有 0 号核在跑，从 Flash 的 `0x2010_0000` 就地执行。它往控制页的 `RUN` 写哪几位，哪几个核就从同一个入口起步；`RUN` 的第 0 位恒为 1。

四个核看到的地址图相同，同一份程序四个核都能跑：程序读控制页的 `HART`（或 `mhartid`）知道自己是谁。`0x8000_0000` 起的 6 MiB 是私有的，地址相同、落在 SDRAM 上各是各的，栈与数据放这里互不相扰；`0x9000_0000` 起的 8 MiB 四个核看到的是同一段。

从 Flash 取一条指令要一百多拍，四个核一起取时再乘四。要跑得快，引导时各核把自己的镜像搬进私有段再跳过去。

### 交互、传数据与刷写

| 做什么 | 怎么做 |
|:--:|:--:|
| 与人交互 | 串口 0（payload 第 0、4 位），115200，USB 转串口。0 号核打字；其余核没有串口，要说的话经信箱发给 0 号核代打 |
| 核与核传数据 | 信箱：写 `TXDEST`、`TXDATA`，对方读 `RXSRC`、`RXDATA`；大块数据放共享段，信箱里只传地址与长度 |
| 与电脑、别的芯片传数据 | 串口；SPI0 接 SD 卡；SPI1 接 W5500 模块出 8P8C 进交换机，或接 `to2610-switch`、`to2610-router`、`to2610-gpu` 的管理口 |
| 刷写程序 | 同 `to2610-kvc`：按住复位，CH341A 在板烧 SPI Flash（`sw/flash.sh`），程序放在 1 MiB 处。大的程序走引导：`sw/boot` 在四个核上各跑一遍，把同一份载荷搬进各自私有的那段 SDRAM，`sw/pack.py` 把引导程序与载荷拼成一个镜像。写坏了重烧即可，片上没有可擦的东西 |

### 与 Chipyard 的做法对照

Chipyard 用 Constellation 生成网络，有两种接法：私有互连是每条 TileLink 总线各配一张专用的网（`MultiNoCConfig`），共享全局互连是一张网承载几条总线（`SharedNoCConfig`），端点到结点的映射写在 `NoCConfigs.scala` 里，几个端点可以落在同一个结点上；每条协议通道各占一个虚拟子网，请求与应答不会互相堵死。

这一颗的网格承载的是核间报文这一种流量，相当于一张专用的网；访存没有搬上去，仍经仲裁走片上总线。报文是单向的、发送不等人，没有「请求等应答」的环，所以不需要虚通道。信箱对网格只认 valid/ready 的报文口，网格换成 Constellation 出的那一种不动信箱。

## 寄存器

四个核看到的地址相同。标「每核一份」的，各核读写的是自己的那一份。

| 地址 | 内容 |
|:--:|:--:|
| `0x0200_0000` | CLINT：第 i 个核的 `msip` 在 `0x0000 + 4i`，`mtimecmp` 在 `0x4000 + 8i`；`mtime` 在 `0xBFF8`，微秒 |
| `0x0C00_0000` | PLIC，只有 0 号核接着它的中断 |
| `0x1000_0000` 起 | 串口、分频、主频、GPIO、SPI0、SPI1、SDRAM 控制器的设置，同 `to2610-kvc` |
| `0x2000_0000` 起 16 MiB | SPI Flash，只读；复位后从 `0x2010_0000` 取指 |
| `0x4004_0000` | 控制页，见下表 |
| `0x4004_0100` | 信箱，每核一份，见下表 |
| `0x8000_0000` 起 6 MiB | 私有的 SDRAM，每核一份 |
| `0x9000_0000` 起 8 MiB | 共享的 SDRAM |

控制页（`0x4004_0000`）：

| 偏移 | 名字 | 读写 | 含义 |
|:--:|:--:|:--:|:--:|
| `0x00` | ID | 读 | `0x4E4F_4334`（"NOC4"） |
| `0x04` | HART | 读 | 发这次访问的核号 |
| `0x08` | RUN | 读写 | 第 i 位放开第 i 个核；第 0 位恒为 1 |
| `0x0C` | IPI | 读写 | 写 1 的位给对应的核挂一个核间中断；读回四个核挂着的 |
| `0x10` | IPIACK | 写 | 写任意值，清掉自己的那一位 |

信箱（`0x4004_0100`，每核一份）：

| 偏移 | 名字 | 读写 | 含义 |
|:--:|:--:|:--:|:--:|
| `0x00` | TXDEST | 读写 | 目的结点号 |
| `0x04` | TXDATA | 写 | 写即发；网格不收或目的号不存在就丢，记在 STAT |
| `0x08` | RXSRC | 读 | 队头那个包的源结点号 |
| `0x0C` | RXDATA | 读 | 队头那个包的载荷，读即出队；空的时候读到 0 |
| `0x10` | STAT | 读写 | 位 0 收到了，位 1 可发，位 2 丢过，位 3 目的号不存在；位 2、3 写 1 清 |
| `0x14` | IE | 读写 | 位 0：收到包时报外部中断 |

各核的机器态外部中断是三个来源的或：信箱收到包、核间中断、PLIC（只有 0 号核）。处理程序先看 `STAT` 的位 0，再看 `IPI` 里自己的那一位。

## 板级连接

引脚与 `to2610-kvc` 逐位相同，kvc、amp、smp、noc 四颗用同一块底板：payload 的 0 到 53 位（串口 0、Flash、SDRAM、SD 卡口、SPI 网卡口、1 位 GPIO），接法见 `to2610-kvc` 的流片说明。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

## 测试说明

整片测试跑在交付的 `to2610_noc.v` 上，测试台是黑盒仓的那一个，带 SDRAM、Flash 与串口的引脚级模型。

| 用例 | 测什么 |
|:--:|:--:|
| hello | 0 号核从 Flash 就地执行：控制页的标识、核号与 `RUN`；私有段 1024 个字按素数步长写了再读，字节写与半字写不动旁边的位；共享段的头尾；段里的地址读得到，一出段就判访问出错 |
| isa | 标准 riscv-tests（`p` 环境，rv32ui、uc、um、ua、mi）逐个在这份 `.v` 上跑，四个核各跑一遍：程序放进那个核私有的那段 SDRAM，Flash 里一小段跳过去，0 号核以外的先由 0 号核放开，测试台盯 `tohost`。不适用的 5 个不跑（Zacas、硬件非对齐访存、PMP、调试触发器）；`mcsr` 核对 `mhartid` 读到 0，只在 0 号核上跑。四个核共 293 次 |
| box | 四个核跑同一份程序。信箱空着时的状态，发给自己，目的号不存在；放开另外三个核，各报一声到；全对全，每个核给别的每个核发 20 个带序号的包，逐个核对源与序号；0 号核压着不收，1 号核连写 40 个，路上装得下的 14 个按序到了，其余丢并记了一笔，写 1 清得掉；2 号核开中断睡着，来一个包叫醒它；3 号核同样睡着，用核间中断叫醒；收回 3 号核再放开，它从头来、再报一声到 |
| atomic | 四个核在共享段上各加两百次。直接加的结果必须少于八百（仿真里是 325）：不丢数说明四个核没有真的在抢，后面几项就什么也证明不了；`amoadd` 得八百；`amoswap` 抢锁、锁里读了再写回，得八百，等锁的次数不能是零；带重试的 LR/SC 得八百，重来的次数不能是零；0 号核预留一个字之后 1 号核写了它，条件写不成、留下的是 1 号核写的数，1 号核写的是别的字时条件写得成；同一个私有地址四个核各写各的记号，谁也没盖掉谁；三个核各设各的计时器，按远近先后到，0 号核的比较值没人动过 |
| rtos | 引导程序在四个核上各跑一遍，把同一个镜像搬进各自私有的那段 SDRAM，校验和对上后跳过去，只有 0 号核打抬头。四个核各起一份 FreeRTOS（V11.2.0，只在机器态），节拍来自各核自己的 `mtimecmp`；另外三个核报到之后，测试台从串口给 0 号核的命令行发命令：`id`；`sum 400` 把 1 到 400 的平方和切成四段，三段经信箱派出去、收齐相加得 21413400；`ps` 问另外三个核的节拍数两次，三个都在走；`bye` 时最低优先级、不让出的任务转过，说明抢占起作用 |

设计的变异（任务 `design-faults`）另跑：把仲裁、信箱、CLINT 的排法里的一处改错、重出 `.v`，`box` 或 `atomic` 里管这一处的那一句必须红。十处：私有段不按核号错开、别的核写了预留的字而预留不作废、没有预留的条件写照样上总线、收回的核不停、信箱的源结点号填错、丢包不记、不存在的目的号不拦、来包不报中断、核间中断清不掉、`mtimecmp` 不按核分格。

## 局限

- 网格只走核间报文。访存不走网格，片外的 Flash、SDRAM 与外设经一个四路仲裁共用，换人要空三拍，四个核都在忙时每个核的速度不到单核的四分之一
- 报文只有一片，载荷 32 位；没有虚通道，没有多片报文
- 发送不等人：网格堵着时丢包并记一笔，重发由软件做
- 只有 0 号核接着串口的中断
- SDRAM 固定 32 MiB、主频固定 50 MHz、没有 JTAG，同 `to2610-kvc`
