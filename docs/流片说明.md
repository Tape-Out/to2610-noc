# to2610-noc 流片说明

流片说明报告的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

2×2 网格上的四个结点，面向 ECOS 2610 班车。四个结点各跑各的程序，结点之间只经网格发报文：0、1 号是 KianV，RV32IMA 带 Sv32；2 号是 Hazard3，RV32IMAC，只有机器态；3 号是 PicoRV32IMAC：上游的 PicoRV32 是 RV32IMC，没有 A 扩展，这一颗的 A 扩展是本仓自己实现的，在 `hwsrc/noc_pico.v`。片外的 SPI Flash、SDRAM 与 `to2610-kvc` 是同一套，四个结点经一个仲裁共用；每个结点有自己的串口。

核与网格都不是这个仓写的：三种核取组织里的黑盒仓 `gf180mcu-kianv-rv32ima-sv32`、`hazard3`、`picorv32`，子模块不动；网格是 Bluespec Haskell 写的 `noc` 库：五口路由器、每口两级缓冲、XY 路由、每个输出口轮转仲裁、valid/ready 握手；片外存储与外设的控制器取 `to2610-kvc` 那棵源码树。本仓自己写的：`box/NocBox.bsv` 是四份信箱加一页控制寄存器，背后例化网格；`hwsrc/noc_tile.v` 把 Hazard3 的 AHB5 口转成片上总线；`hwsrc/noc_pico.v` 是 PicoRV32IMAC 的结点，连同它的协处理器；`hwsrc/noc_arb.v` 是四路仲裁，连同地址换算与独占访问的预留表；`hwsrc/noc_time.v` 是微秒计数；`patch/noc.patch` 在 kvc 的源码树上接进上面几样。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 0、1 号结点 | KianV | RV32IMA、Zicsr、Zifencei，机器态、监管态与用户态，Sv32；各有自己的 CLINT、PLIC 与串口 |
| 2 号结点 | Hazard3 | RV32IMAC、Zbb、Zicsr、Zifencei、Zicntr，只有机器态 |
| 3 号结点 | PicoRV32IMAC | 上游 PicoRV32 的 RV32IMC，乘除、压缩指令、桶形移位、快速乘法、中断、64 位计数器全开；A 扩展的 Zalrsc 与 Zaamo 是本仓自己实现的，经协处理器口接上，`fence.i` 与一条签名指令也在那里 |
| 网格 | 2×2，XY 路由 | 单片报文：目的 8 位、源 8 位、载荷 32 位；源结点号由硬件填 |
| 信箱 | 每个结点一份 | 发送不等人，网格不收就丢并记一笔；接收缓冲 4 个包，可报中断 |
| 存储 | 片外 SDRAM 64 MiB、SPI Flash | 私有段：两颗 KianV 各 24 MiB，另两个结点各 4 MiB；四个结点共享 8 MiB；Flash 四个结点都读得到 |
| 原子操作 | LR、SC 与 AMO 跨结点原子 | 在仲裁这一处裁决：按物理地址记预留，别的结点写了被预留的字，预留作废 |
| 计时器与核间中断 | 每个结点自己的 CLINT；控制页的 `IPI` | 同一个地址各看各的：每个结点都是自己那个世界里的 0 号 hart，`mhartid` 都是 0 |
| 结点的起停 | 控制页的 `RUN` | 复位后只有 0 号结点跑；收回一个结点要等它手上那次访问做完 |
| 外设 | 同 `to2610-kvc` | SD 卡口、SPI 网卡口、1 位 GPIO 只归 0 号结点，别的结点读到 0 |

### 四个结点怎么起

复位后只有 0 号结点在跑。它往控制页的 `RUN` 写哪几位，哪几个结点就起步；`RUN` 的第 0 位恒为 1。KianV 与 Hazard3 从 Flash 的 `0x2010_0000` 取指，PicoRV32IMAC 的指令集不同，从 `0x2018_0000` 取指，程序另编一份。

四个结点看到的地址图相同。各核的 `mhartid` 都是 0，程序读控制页的 `HART` 知道自己是哪个结点。`0x8000_0000` 起是私有段，地址相同、落在 SDRAM 上各是各的；`0x9000_0000` 起的那一段四个结点看到的是同一段。

存储与外设是共用的，一个结点占着总线时别的结点要等。从 Flash 取一条指令要一百多拍：程序要跑得快，引导时搬进私有段再跳过去；没活干的结点应当等中断，不要就地在 Flash 里空转。

### 自己实现的 A 扩展

上游的 PicoRV32 没有 A 扩展。`lr.w`、`sc.w` 与九条 AMO 是本仓写的一个协处理器做的，在 `hwsrc/noc_pico.v`，核的子模块不动；riscv-tests 的 rv32ua 在这个结点上全过，它与两颗 KianV、一颗 Hazard3 在同一个字上抢，一个不丢。

PicoRV32 的协处理器口 PCPI 只递指令字与两个源寄存器。协处理器自己带一个访存口，与核的访存口二选一接到仲裁上：核等协处理器时自己的访存口空着。

| 指令 | 做什么 |
|:--:|:--:|
| `lr.w`、`sc.w` | 独占读并记预留；预留还在才独占写，`rd` 回 0 或 1 |
| `amoswap.w` 等九条 | 独占读、算、独占写；别的结点在中间写了这个字、仲裁回没写成，就从读重来 |
| `fence.i` | 空操作：没有指令缓存 |
| 签名指令 | custom-1，操作码 `0x2b`，funct3 与 funct7 都是 0。`rs1` 为 0 时 `rd` 得 `0x656B6568`，为 1 时得 `0x38323231`，其余得 0。两个字按小端存进内存就是 `heke1228` |

C 里这样用签名指令：

```c
static inline unsigned sig(unsigned i) {
  unsigned r;
  __asm__(".insn r 0x2b, 0, 0, %0, %1, x0" : "=r"(r) : "r"(i));
  return r;
}
unsigned w[3] = {sig(0), sig(1), 0};   /* (char *)w 就是 "heke1228" */
```

custom-0 被 PicoRV32 自己的中断指令占着，所以用 custom-1；标准程序用不到这个操作码，它的别的编码照旧报非法指令。地址没对齐的原子指令协处理器不应答，核按非法指令陷入。

### 交互、传数据与刷写

| 做什么 | 怎么做 |
|:--:|:--:|
| 与人交互 | 每个结点一路串口，115200：0 号在 payload 第 0、4 位，同 `to2610-kvc`；1、2、3 号的 RX、TX 依次在第 54 至 59 位 |
| 结点之间传数据 | 信箱：写 `TXDEST`、`TXDATA`，对方读 `RXSRC`、`RXDATA`；大块数据放共享段，信箱里只传地址与长度 |
| 与电脑、别的芯片传数据 | 串口；0 号结点的 SPI0 接 SD 卡，SPI1 接 W5500 模块出 8P8C 进交换机，或接 `to2610-switch`、`to2610-router`、`to2610-gpu` 的管理口 |
| 刷写程序 | 同 `to2610-kvc`：按住复位，CH341A 用 `sw/flash.sh` 在板烧 SPI Flash。`sw/pack.py` 把引导程序、目录、各结点的载荷、PicoRV32IMAC 的程序拼成一个镜像：引导程序在 1 MiB 处，目录在其后 64 KiB 处，PicoRV32IMAC 的程序在 1.5 MiB 处，载荷从 2 MiB 起，几个结点可以共用一份。引导程序照目录把自己的那份逐段搬进私有的那段 SDRAM，各在自己的串口上报进度。写坏了重烧即可，片上没有可擦的东西 |

### 与 Chipyard 的做法对照

Chipyard 用 Constellation 生成网络，有两种接法：私有互连 `MultiNoCConfig` 是每条 TileLink 总线各配一张专用的网，共享全局互连 `SharedNoCConfig` 是一张网承载几条总线，端点到结点的映射写在 `NoCConfigs.scala` 里，几个端点可以落在同一个结点上；每条协议通道各占一个虚拟子网，请求与应答不会互相堵死。

这一颗的网格承载的是结点间的报文这一种流量，相当于一张专用的网；访存没有搬上去，仍经仲裁走片上总线。报文是单向的、发送不等人，没有「请求等应答」的环，所以不需要虚通道。信箱对网格只认 valid/ready 的报文口，网格换成 Constellation 出的那一种不动信箱。

## 寄存器

四个结点看到的地址相同。标「各一份」的，各结点读写的是自己的那一份。

| 地址 | 内容 |
|:--:|:--:|
| `0x0200_0000` | CLINT，各一份：`msip` 在 `0x0000`，`mtimecmp` 在 `0x4000`，`mtime` 在 `0xBFF8`，微秒 |
| `0x0C00_0000` | PLIC，两颗 KianV 各一份：源 10 是自己的串口，11 是信箱来包，12 是核间中断。另两个结点读到 0 |
| `0x1000_0000` 起 | 串口各一份；分频与主频四个结点共用；`0x1000_0018` 读到的是这个结点私有段的大小；GPIO、SPI0、SPI1 只归 0 号结点，同 `to2610-kvc` |
| `0x2000_0000` 起 16 MiB | SPI Flash，只读 |
| `0x4004_0000` | 控制页，见下表 |
| `0x4004_0100` | 信箱，各一份，见下表 |
| `0x8000_0000` 起 | 私有的 SDRAM，各一份：0、1 号 24 MiB，2、3 号 4 MiB |
| `0x9000_0000` 起 8 MiB | 共享的 SDRAM |

控制页 `0x4004_0000`：

| 偏移 | 名字 | 读写 | 含义 |
|:--:|:--:|:--:|:--:|
| `0x00` | ID | 读 | `0x4E4F_4334`，ASCII 是「NOC4」 |
| `0x04` | HART | 读 | 发这次访问的结点号 |
| `0x08` | RUN | 读写 | 第 i 位放开第 i 个结点；第 0 位恒为 1 |
| `0x0C` | IPI | 读写 | 写 1 的位给对应的结点挂一个核间中断；读回四个结点挂着的 |
| `0x10` | IPIACK | 写 | 写任意值，清掉自己的那一位 |

信箱 `0x4004_0100`，各结点一份：

| 偏移 | 名字 | 读写 | 含义 |
|:--:|:--:|:--:|:--:|
| `0x00` | TXDEST | 读写 | 目的结点号 |
| `0x04` | TXDATA | 写 | 写即发；网格不收或目的号不存在就丢，记在 STAT |
| `0x08` | RXSRC | 读 | 队头那个包的源结点号 |
| `0x0C` | RXDATA | 读 | 队头那个包的载荷，读即出队；空的时候读到 0 |
| `0x10` | STAT | 读写 | 位 0 收到了，位 1 可发，位 2 丢过，位 3 目的号不存在；位 2、3 写 1 清 |
| `0x14` | IE | 读写 | 位 0：收到包时报中断 |

中断各结点走各自的那一套：

| 结点 | 计时器、软件中断 | 信箱来包、核间中断、串口 |
|:--:|:--:|:--:|
| KianV | 自己的 CLINT，标准的 MTIP、MSIP | 经自己的 PLIC：源 11、12、10 |
| Hazard3 | 自己的 CLINT | 外部中断线 0、1、2 |
| PicoRV32IMAC | 它的 3、4 号中断 | 它的 6、5、7 号中断；仲裁判访问出错时起 2 号总线错 |

## 板级连接

payload 的 0 到 53 位与 `to2610-kvc` 逐位相同：串口 0、Flash、SDRAM、SD 卡口、SPI 网卡口、1 位 GPIO，接法见 `to2610-kvc` 的流片说明。底板与 kvc 的相同，只是 SDRAM 换成 64 MiB 的 MT48LC32M16A2 一类，同封装、同引脚，列地址多一位。54 到 59 位是另外三路串口：54、56、58 是 1、2、3 号结点的 RX，55、57、59 是 TX，各接一个 USB 转串口。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

## 测试说明

整片测试跑在交付的 `to2610_noc.v` 上，测试台是黑盒仓的那一个，带 SDRAM、Flash 与串口的引脚级模型；1 至 3 号结点的串口接在测试台多出来的三路上，各有一份脚本。程序编两份拼进一个 Flash 镜像：KianV 与 Hazard3 用公共的 `rv32ima` 那一份，PicoRV32IMAC 在 `htest/pico` 另编一份。

| 用例 | 测什么 |
|:--:|:--:|
| hello | 0 号结点从 Flash 就地执行：控制页的标识、结点号与 `RUN`；私有段 1024 个字按素数步长写了再读，字节写与半字写不动旁边的位；共享段的头尾；段里的地址读得到，一出段就判访问出错 |
| isa | 标准 riscv-tests 四个结点各跑各的一套，共 294 次：两颗 KianV 各是 rv32ui、um、ua、mi、si 加黑盒仓那条 AMO 写半边缺页的定向测试；Hazard3 是 rv32ui、uc、um、ua、mi；PicoRV32IMAC 没有机器态的 CSR，换用环境头 `htest/isa/env-pico`，跑 rv32ui、uc、um、ua。程序放进那个结点私有的那段 SDRAM，0 号以外的先由 0 号放开，测试台盯 `tohost`。Zacas、硬件非对齐访存、PMP、调试触发器 5 个不适用，不跑 |
| box | 信箱空着时的状态，发给自己，目的号不存在；放开另外三个结点，各报一声到；全对全，每个结点给别的每个结点发 20 个带序号的包，逐个核对源与序号；0 号压着不收，1 号连写 40 个，路上装得下的 14 个按序到了，其余丢并记了一笔，写 1 清得掉；Hazard3 开中断睡着，来一个包叫醒它；PicoRV32IMAC 同样睡着，用核间中断叫醒；收回 3 号再放开，它从头来、再报一声到 |
| irq | 每个结点把自己的五路中断各点一次：计时器、软件中断、信箱来包、核间中断、串口，共二十路。每一路由结点自己引起，中断里按核认到的来路核对：KianV 是 `mcause` 加向 PLIC 认领到的源号，PicoRV32IMAC 是中断入口给的位图，Hazard3 的三根外部线并成一路、按源头的状态分 |
| atomic | 四个结点在共享段上各加两百次。直接加的结果必须少于八百：不丢数说明四个结点没有真的在抢，后面几项就什么也证明不了；`amoadd` 得八百；`amoswap` 抢锁、锁里读了再写回，得八百，等锁的次数不能是零；带重试的 LR/SC 得八百，重来的次数不能是零；0 号预留一个字之后 1 号写了它，条件写不成、留下的是 1 号写的数，1 号写的是别的字时条件写得成；同一个私有地址四个结点各写各的记号，谁也没盖掉谁；三个结点各设各的计时器，按远近先后到，0 号的比较值没人动过 |
| uart | 四个结点各在自己的串口上报一声：四路各有一份脚本等那个结点自己的那一句，每一路上只有这一句，别的结点的字不漏过来。报之前各结点把 16550 别的寄存器写一遍：写了不挂、不当成发字，线路状态那个字里另外三个读回 0 |
| sig | PicoRV32IMAC 执行签名指令，读到的两个字经信箱交给 0 号结点，串口打出 `heke1228`；`rs1` 取别的数读到 0；custom-1 的别的编码报非法指令，恰好一次 |
| rtos | 引导程序在 KianV 与 Hazard3 上各跑一遍，照目录把同一份载荷搬进各自私有的那段 SDRAM，校验和对上后跳过去，各在自己的串口上报进度。三个结点各起一份 FreeRTOS V11.2.0，只在机器态；节拍来自各自的 `mtimecmp`，堆是各段之后到段顶的那一截，KianV 23 MiB、Hazard3 3 MiB，报到时核对；PicoRV32IMAC 就地跑一个不带 RTOS 的同口令程序，没活时等中断。另外三个结点报到之后，测试台从串口给 0 号的命令行发命令：`id`；`sum 400` 把 1 到 400 的平方和切成四段，三段经信箱派出去、收齐相加得 21413400；`ps` 问另外三个结点的节拍数两次，三个都在走，PicoRV32IMAC 回的是毫秒数；`bye` 时最低优先级、不让出的任务转过，说明抢占起作用 |
| echo | 一个镜像里各结点搬各自的那一份：0 号是发问的程序，Hazard3 是回声，PicoRV32IMAC 的回声就地跑。0 号的引导程序照目录先放开那两个结点，再给两个回声各发八个数，回来的都加了一、来路对 |

两份 Linux 另跑，分两段。`linux`：两颗 KianV 各把一份 `to2610-kvc` 的 Linux 镜像搬进自己私有的那段 SDRAM，设备树里的内存由 `sw/linux-image.py` 改成 24 MiB；两份同时起，各在自己的串口上起到 shell，各读到自己的结点号；另两个结点跑回声。仿真一天上下，流水线上分几棒接力，脚本 `htest/linux-boot.sh`。`linux-box`：从两份都到 shell 的断点接着跑，0 号的 Linux 问 Hazard3 的回声、1 号的问 PicoRV32IMAC 的回声，两份 Linux 经信箱互发一个字，共享段上各写一个字、对方读到；信箱与共享段都经 `devmem` 读写，脚本 `htest/linux-box.sh`。这一段托管机六小时跑不完，从流水线的断点在本机接着跑完。

设计的变异另跑，任务 `design-faults`：把一处改错、重出 `.v`，`box`、`irq`、`atomic`、`sig` 或 `uart` 里管这一处的那一句必须红。二十二处：私有段不错开、别的结点写了预留的字而预留不作废、没有预留的条件写照样上总线、收回的结点不停、KianV 的 AMO 读写之间不锁总线、信箱的源结点号填错、丢包不记、不存在的目的号不拦、来包不报中断、核间中断清不掉、CLINT 不分结点、KianV 的 LR 与 SC 不走独占、PicoRV32IMAC 的 AMO 没写成不重来、PicoRV32IMAC 收不到核间中断、签名指令的值错一位、串口不分结点、线路状态只认按字节的地址、线路状态那个字的写没人应答、别的字节的写也当成发字、PLIC 的信箱与核间中断两个源接反、Hazard3 的串口中断没接、PicoRV32IMAC 的软件中断没接。

## 局限

- 网格只走结点间的报文。访存不走网格，片外的 Flash、SDRAM 与外设经一个四路仲裁共用，换人要空三拍，四个结点都在忙时每个结点的速度不到单独跑时的四分之一
- 报文只有一片，载荷 32 位；没有虚通道，没有多片报文
- 发送不等人：网格堵着时丢包并记一笔，重发由软件做
- 四个结点同一个时钟、同一个波特率分频
- PicoRV32IMAC 没有访问出错的口，仲裁判出错时那次访问照常收尾，另起它的 2 号中断；它的预取在 `fence.i` 之前，紧跟在 `fence.i` 后面的那一条指令不能是刚改写的
- SDRAM 固定 64 MiB、主频固定 50 MHz、没有 JTAG，同 `to2610-kvc`
